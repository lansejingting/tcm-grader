## 1. 背景与问题定义

### 1.1 行业痛点

中药材商品规格等级鉴定目前高度依赖人工经验：

- **主观性强**：色泽、饱满度、缺陷率等维度靠目测判断，不同质检员结论不一致，同一个人不同时段结论也会漂移；
- **标准难落地**：SB/T 11173-2016《中药材商品规格等级通则》及 T/CACM 1021 系列标准对每个品种规定了多档等级，但一线人员难以逐条对照执行；
- **效率瓶颈**：进货验收、交易定价场景需要快速出结果，人工逐批目测耗时长；
- **经验断层**：老药工经验难以沉淀和复制，新人培养周期长。

### 1.2 解决思路

用多模态大模型模拟"有经验的质检员"的判断过程：

1. **看图辨药**——识别药材品种（模拟"这是什么"）；
2. **对照标准**——检索该品种的商品规格等级规则（模拟"查标准"）；
3. **逐维度比对定级**——按木桶效应取最差维度定档（模拟"下结论"）；
4. **人工复核闭环**——AI 给出初判 + 证据，人做最终决定，复核结果沉淀回流。

产品定位：**辅助决策工具，不替代人工最终判定**。

## 2. 目标用户与使用场景

### 2.1 用户画像

| 用户 | 场景 | 核心诉求 | 使用频次 |
|---|---|---|---|
| 药企质检员 | 原料进货验收 | 快速初筛 + 留痕可追溯 | 每日高频 |
| 药材市场商户 | 交易现场分级定价 | 秒级参考价，减少扯皮 | 每日高频 |
| 药农 / 合作社 | 采收后初步分拣 | 不懂标准也能分出好差 | 季节性 |

### 2.2 用户故事

- 作为**质检员**，我上传一张药材照片，系统告诉我品种、等级和判定依据，我核对后一键归档，这样验收单有图有证据。
- 作为**质检员**，当 AI 认错品种时，我可以在下拉框改成正确品种，系统只重新定级（不用重新识别），这样改判成本很低。
- 作为**商户**，我看不懂专业术语，但系统用"色泽/大小/饱满度/缺陷"四张证据卡告诉我为什么定这个等级，短板在哪一目了然。
- 作为**管理者**，所有复核记录自动落日志，出现质量纠纷时可以回溯当时 AI 怎么判的、人怎么定的。

## 3. 产品目标与指标体系

### 3.1 北极星指标

**复核通过率** = AI 初判被人直接确认（未改判）的比例。

选择理由：它同时反映识别与定级的综合质量，且可从复核日志直接统计，是"AI 判断值得信任程度"的业务表达。

### 3.2 指标体系（模型指标 → 业务指标映射）

| 层级 | 模型指标 | 业务指标 | 当前水位（MVP 实测） |
|---|---|---|---|
| 识别 | Top-1 准确率（20 类） | 复核改判率 | 55.7% ~ 57.7%（3 轮 benchmark） |
| 识别 | 同图多次一致率 | 判断可信度 | 95% |
| 定级 | 规则一致性（等级名严格对齐规则库） | 标准可执行性 | 100%（动态注入等级表后） |
| 定级 | 置信度分布 | 分流准确性 | 阈值 0.70 自动标记复核 |
| 成本 | 单张 token 消耗 | 单张处理成本 | ~1,616 token/张（识别+定级两阶段） |
| 效率 | 端到端时延 | 用户等待时长 | 秒级（实测 8~30 秒/张） |

> **关键产品判断**：当前识别准确率不适合无人值守全自动定级，因此 v1 定位为"**AI 初判 + 人工确认**"的人机协同形态——这正是复核台存在的理由。指标目标不是一步到 99%，而是通过复核闭环持续抬升复核通过率。

## 4. 解决方案总览

```
图片输入 → ①品种识别（qwen-vl-max + 药典特征 + 混淆要点）
        → ②规则检索（FAISS 语义检索，按品种精确过滤）
        → ③多模态定级（木桶效应 + 一票否决）
        → ④结果解释（四维证据卡 + 短板高亮）
        → ⑤人工复核（改判 / 通过 / 返回人工）
        → ⑥复核日志（留痕 + 数据回流入口）
```

三条关键产品策略：

1. **置信度分层分流**：定级置信度 < 0.70 或模型自报 review_flag 时，前端醒目提示"需复核"，把有限的人工注意力投向高风险样本；
2. **把行业标准翻译成模型可执行的规则**：木桶效应（任一维度不达标即降档）+ 一票否决（霉变/虫蛀直接等外品）写进定级 Prompt，等级名从规则库动态注入，杜绝模型编造等级；
3. **解释先行**：强制输出四个维度的观察证据 + 木桶短板维度，让复核员"看得懂、改得准、敢签字"。

## 5. 功能需求

### 5.1 功能列表与优先级

| 编号 | 功能 | 优先级 | 状态 |
|---|---|---|---|
| F1 | 图片输入（上传 / 拖拽 / 数据集示例选择） | P0 | 已实现 |
| F2 | AI 品种识别（含置信度与识别依据） | P0 | 已实现 |
| F3 | 智能定级（检索该品种规则，木桶效应定档） | P0 | 已实现 |
| F4 | 四维证据展示（色泽/大小/饱满度/缺陷，短板高亮） | P0 | 已实现 |
| F5 | 品种改判 + 重新定级（跳过识别，只跑定级） | P0 | 已实现 |
| F6 | 复核结论（定级通过 / 返回人工） | P0 | 已实现 |
| F7 | 复核日志（时间/图片/改判/结论，最近 50 条） | P0 | 已实现 |
| F8 | Top-3 候选品种二次裁决 | P1 | 规划中 |
| F9 | 批量图片导入 + 队列处理 | P1 | 规划中 |
| F10 | 复核报告导出（PDF/Excel 归档） | P1 | 规划中 |
| F11 | 复核数据回流 → few-shot 案例库 | P2 | 规划中 |
| F12 | 移动端 / 小程序入口 | P2 | 规划中 |

### 5.2 核心流程（人工复核台）

1. 用户上传或选择图片 → 预览确认；
2. 点击"开始识别与定级"，系统返回：品种、识别置信度、等级、定级置信度、四维证据、短板维度；
3. 若品种识别有误：下拉更正品种 → "重新定级"（只调一次模型，时延减半）；
4. 人工评估证据卡后点击"定级通过"（归档）或"返回人工"（标记专家复核）；
5. 复核日志实时更新，记录改判情况（`herb_corrected` 字段）。

### 5.3 明确不做的事（MVP 边界）

- **不做全自动无人定级**：责任与合规要求最终判定必须由人确认；
- **不做品种外的开放识别**：限定 20 种目标药材，避免开放域幻觉；
- **不做称重/尺寸自动测量**：v1 以视觉特征定性判断为主，量化测量留待硬件方案。

## 7. 数据与评估计划

### 7.1 已完成的评估（MVP 实测数据）

- **三轮纵向 benchmark**（100 张固定抽样 × 3 次）：识别准确率 55.7% → 57.7% → 57.7%，同图稳定率 95%，单张 1,616 token；
- **Prompt 专项迭代**（12 个易错品种 60 张）：易错品种识别 26.7% → 46.7%（+20pp），其中砂仁 0/5 → 5/5、瓜蒌 2/5 → 5/5；
- **Badcase 人工归因**（15 张顽固错误图）：
  - 数据分布问题：桃仁 4/5 为焯去皮加工品（与药典描述的带皮形态不符）；
  - 图片质量问题：地肤子 5/5 为碎粒特写，缺乏诊断特征；
  - 模型能力问题：连翘 5/5 标注正确仍误判 → 纳入 Prompt 混淆要点强化。

### 7.2 迭代策略（数据驱动）

错误不是均匀分布而是**系统性聚集**的（如草豆蔻曾吸走 16 次误判），因此优先级：
混淆对 Prompt 强化（成本低见效快）→ Top-3 二次裁决 → 复核日志回流 few-shot → 领域微调。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 识别准确率不满足全自动要求 | 用户信任受损 | 明确辅助定位；置信度分流；人机协同兜底 |
| 训练/测试数据分布偏差（加工品、碎粒图） | 特定品类系统性误判 | 建立数据采集规范；badcase 归因驱动补数据 |
| 大模型幻觉（编造等级/证据） | 结论不可信 | 等级表动态注入 + JSON 严格约束 + 证据卡强制对齐规则 |
| 单一模型供应商依赖 | 服务与成本风险 | 兼容 OpenAI 协议，可切换模型 |
| 责任界定争议 | 合规风险 | 产品全程标注"辅助参考"，最终判定人工确认并留痕 |
